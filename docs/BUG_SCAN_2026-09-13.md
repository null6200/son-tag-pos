## Critical

- [x] **FIXED (commit a47b5423) — Purchases feature is dead end-to-end.**
      `backend/src/purchases/purchases.controller.ts` stubbed every endpoint with
      `notImplemented()` (501); frontend called `/purchase-orders`, backend only
      exposed `/purchases`. Rebuilt: real CRUD + status state machine
      (PENDING → APPROVED → RECEIVED/CANCELLED), inventory + StockMovement
      credited exactly once on RECEIVED, route renamed to `/purchase-orders`,
      `Purchase.jsx` now has a real product picker. Requires
      `npx prisma generate && npx prisma migrate deploy` for migration
      `20260913180000_add_purchase_status_and_user`.
- [x] **CORRECTED — Customers was NOT fully stubbed.** Original scan was wrong:
      it was based on a grep for `notImplemented()` without reading the full
      files. `customers.controller.ts`/`.service.ts` `list/create/update/remove`
      were already implemented and working — only 5 unused `no-sell/*` endpoints
      are real stubs (nothing in the frontend calls them; left alone, since
      `Order` has no `customerId` link so they can't be implemented correctly
      without a larger schema/UX change).
      **The actual bug (fixed, commit 924505ea): Suppliers data loss.**
      `suppliers.service.ts` silently dropped `email`/`phone`/`contactPerson`/
      `address`/`businessName` on create and update — the Prisma model never had
      those columns even though both `Purchase.jsx`'s supplier form and
      `Contacts.jsx`'s shared contact form collect them. Added the columns
      (migration `20260913190000_add_supplier_customer_contact_fields`) and a
      `resolveNaming()` helper in the service to reconcile the two forms, which
      disagree on whether `name` means the business name or the contact person.
      Also added `Customer.businessName` (same shared Contacts form writes it).
      Requires another `npx prisma generate && npx prisma migrate deploy` run.
- [ ] **JWT secret falls back to a hardcoded value.** `auth.module.ts`, `auth.service.ts`,
      `jwt.strategy.ts` all do `process.env.JWT_SECRET || 'devsecret'`. Local `.env`
      currently has `JWT_SECRET=` blank. Should fail startup instead of silently using
      a known secret (forgeable tokens).

## High

- [ ] **Inventory "release reservations" is fragile.** `inventory.service.ts` encodes
      reservation keys as substrings inside `StockMovement.referenceId`
      (`|RESV|<key>`, matched with `.includes()`, no closing delimiter → possible
      false-match between similar keys). Also rescans the branch's entire ADJUST
      history every call (no date bound — will slow down over time). Heavy leftover
      `console.log` debugging suggests this path has caused repeat issues.
- [ ] **Purchases (dead) code never updates inventory and isn't transactional.**
      Even the unreachable `purchases.service.ts` `create()` never writes
      `Inventory`/`StockMovement` rows, and does purchase→items→payments as 3
      separate non-atomic writes (no `$transaction`) — a mid-request failure leaves
      an orphaned purchase with no items.
- [ ] **TaxRates and Units modules fully stubbed** (`notImplemented()`). Units has
      zero frontend references found — may be intentionally deferred, confirm scope.

## Medium

- [ ] **`as any` casts on Prisma client/DTOs across ~36 backend files** — bypasses
      TypeScript checks; schema/field typos fail at runtime instead of build time.
- [ ] **50+ raw `console.log`/`console.error` calls** in auth, WebSocket gateway,
      inventory, orders, `main.ts` instead of the existing Winston logger. `main.ts`
      has a `/status` debug block logging full request bodies/headers.
- [ ] **Access token stored in `localStorage`/`sessionStorage`** (`src/lib/api.js`,
      `src/lib/socket.js`) — more XSS-exposed than an httpOnly cookie.
