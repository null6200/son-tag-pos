# Bug & Glitch Scan — 2026-09-13

Static code review (no runtime testing, no full 34-module line-by-line audit).
Use this as a checklist: tick items off as you decide to fix/skip them, and add
new findings/planned changes at the bottom.

## Critical

- [ ] **Purchases feature is dead end-to-end.** `backend/src/purchases/purchases.controller.ts`
      stubs every endpoint with `notImplemented()` (501). Separately, the frontend
      (`src/lib/api.js` → `purchaseOrders`) calls `/purchase-orders`, but the backend
      only exposes `/purchases` — route doesn't exist either way. `Purchase.jsx`
      (create/list/receive PO) does nothing today.
- [ ] **Customers feature is dead end-to-end.** `backend/src/customers/customers.controller.ts`
      and `.service.ts` are fully stubbed. `Contacts.jsx` actively calls
      `api.customers.list/create/update/remove` — every customer action throws 501.
- [ ] **JWT secret falls back to a hardcoded value.** `auth.module.ts`, `auth.service.ts`,
      `jwt.strategy.ts` all do `process.env.JWT_SECRET || 'devsecret'`. Local `.env`
      currently has `JWT_SECRET=` blank. Should fail startup instead of silently using
      a known secret (forgeable tokens).

## High

- [ ] **Inventory "release reservations" is fragile.** `inventory.service.ts` encodes
      reservation keys as substrings inside `StockMovement.referenceId`
      (`|RESV|<key>`, matched with `.includes()`, no closing delimiter → possible
      false-match between similar keys). Also rescans the branch's entire ADJUST
      history every call (no date bound — will slow down over time). Heavy leftover
      `console.log` debugging suggests this path has caused repeat issues.
- [ ] **Purchases (dead) code never updates inventory and isn't transactional.**
      Even the unreachable `purchases.service.ts` `create()` never writes
      `Inventory`/`StockMovement` rows, and does purchase→items→payments as 3
      separate non-atomic writes (no `$transaction`) — a mid-request failure leaves
      an orphaned purchase with no items.
- [ ] **TaxRates and Units modules fully stubbed** (`notImplemented()`). Units has
      zero frontend references found — may be intentionally deferred, confirm scope.

## Medium

- [ ] **`as any` casts on Prisma client/DTOs across ~36 backend files** — bypasses
      TypeScript checks; schema/field typos fail at runtime instead of build time.
- [ ] **50+ raw `console.log`/`console.error` calls** in auth, WebSocket gateway,
      inventory, orders, `main.ts` instead of the existing Winston logger. `main.ts`
      has a `/status` debug block logging full request bodies/headers.
- [ ] **Access token stored in `localStorage`/`sessionStorage`** (`src/lib/api.js`,
      `src/lib/socket.js`) — more XSS-exposed than an httpOnly cookie.

## Low / Housekeeping

- [ ] Stray files in repo root: `.DS_Store`, `__MACOSX/`, `out.bin` (0 bytes), five
      `vite.config.js.timestamp-*.mjs` files, `temp_env.txt` — safe to delete.
- [ ] `.env.example` missing `POSTGRES_USER` that real `.env` has — keep in sync.
